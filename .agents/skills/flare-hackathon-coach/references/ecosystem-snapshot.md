# Flareエコシステム・スナップショット & ポジショニング

出典: ユーザー提供の調査報告書（基準日 2026年8月2日）。TVLやアクティブアドレス等の数値は
**その時点のスナップショット**であり、ピッチ資料に転記する際は必ず「調査時点」を明記し、
可能ならDefiLlama等で当日の値を再確認すること。数値そのものより、大小関係・トレンドの説明に使う。

## ポジショニングの一文

> Flareは「高速なEVMチェーン」ではなく、価格・時系列データ、外部チェーンのトランザクション、
> Web APIの応答を**ネットワーク内蔵型のデータプロトコル**としてスマートコントラクトへ供給する
> データ特化型レイヤー1である。

ハッカソンのピッチでは「Ethereumより速く安いチェーン」という売り方をしない。BSCやPolygonは
同等以上の表面速度を持ち、L2はEthereum流動性を持つため、この土俵では勝てない。勝ち筋は
**「外部データを検証して、その結果から即座に資産を動かせるEVM」**という一点に絞る。

## 強み・弱みの要約

| 強み | 意味 |
|---|---|
| Enshrined Oracle | FTSO/FDCがプロトコル報酬・validatorに直結。外部サービスでなくL1機能 |
| 非EVM資産への焦点 | XRP/BTC/DOGEをFAssetsでDeFiへ接続できる |
| 一署名XRPL UX | Smart AccountsでEVM wallet・FLR gasを意識させずに操作可能 |
| 低遅延FTSO | 約1.8秒ごとの価格更新。清算・リスク制御向き |
| TEE/FCC | 秘密計算とオンチェーン検証を組み合わせられる |

| 弱み | 意味 |
|---|---|
| ネットワーク効果 | Ethereum/L2/BSC/Polygonに比べ資産・開発者・監査済みコードが薄い |
| Oracleリスクの相関 | Validator・FTSO/FDC provider・DA Layer・FAssets agentが同一経済圏 → 障害が波及しやすい |
| 一般的DEX/NFT/Lendingの再実装は無価値 | Ethereumで飽和した実装をそのまま移植しても差別化にならない |

## 主要EVMチェーンとの比較（要点のみ）

| チェーン | ブロック/確定性 | Flareとの相対評価 |
|---|---|---|
| Flare | 約1.8秒、単一スロットfinality | 基準 |
| Ethereum | 12秒slot、複数epochでfinality | 圧倒的な流動性・分散性だが低速・高コスト |
| BSC | 0.45秒block | 同等以上に速いがvalidator集中 |
| Polygon PoS | 1.5秒block | 消費者アプリ向け、Flareと拮抗 |
| Avalanche C-Chain | sub-second〜約1秒finality | Snowman系で技術的に近い競合 |
| Optimism/Arbitrum | sequencerの高速soft confirmation | Ethereum流動性を持つが二層fainality |

結論: 速度だけでは差別化できない。Flareの土俵はOracle内蔵・非EVM資産・一署名UXである。

## 助成・審査エコシステム

Flare Grantsは独自性・Flareエコシステムへの利益・実行能力・GTM・ロードマップ・FTSO/FDC統合・
過去経験を重視する。ETHGlobalのFlare賞でも「動作するアプリ、live URL、OSS repo、README記載の
デプロイ済みcontract address、Flareプロトコルの実質的使用」が評価要件として繰り返し出ている。
→ 審査対策は「高度な実装」より「要件を成果物として明示すること」から逆算する。
