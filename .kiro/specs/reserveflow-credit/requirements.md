# Requirements Document

## Introduction

ReserveFlow Creditは、外部チェーンに保有される準備金を検証可能な信用力へ変換し、資産を売却または移動せずにFlare上でテスト用のステーブルコインを借りられるようにする、Flareハッカソン向けMVPである。対象プロダクトは、準備金の検証、現在価値の評価、保守的な与信枠の算出、借入・返済、データ鮮度を考慮したリスク制御を一連の体験として提供する。

## Boundary Context

- **In scope**: Coston2上での単一ユーザー向けの準備金登録、FDCによる単一の外部チェーン／資産の入出金証明、FTSO価格に基づく与信、テスト用ステーブルコインの借入・返済、リスク監視。
- **Out of scope**: 実資産または法定通貨による融資、複数チェーン・複数資産の同時対応、複雑な信用履歴スコア、変動金利、完全分散型の清算市場、KYC・法務対応、メインネット運用。
- **Adjacent expectations**: FDCは外部チェーン上のイベントの検証に、FTSOは資産の価格評価に使用する。プロダクトは検証済みデータのみを与信判断へ用いる。

## Requirements

### Requirement 1: MVP対象とポジションの開始
**Objective:** As a デモ利用者, I want 対象範囲が明確な信用ポジションを開始する, so that 検証可能な最小フローを完結して体験できる

#### Acceptance Criteria
1. ユーザーがMVPを開始するとき、ReserveFlow CreditはCoston2上の単一の外部チェーンおよび単一の対象資産に限定した信用ポジションを提供しなければならない。
2. ユーザーが対象外のチェーンまたは資産を選択したとき、ReserveFlow Creditはその選択を受け付けず、対象外である理由を表示しなければならない。
3. ReserveFlow Creditは、各ポジションについて準備金、評価額、借入残高、利用可能額、健全性状態を一貫して識別できなければならない。

### Requirement 2: 準備金アカウントの登録
**Objective:** As a 準備金保有者, I want 外部チェーンの準備金アカウントを登録する, so that その準備金を検証と与信の対象にできる

#### Acceptance Criteria
1. ユーザーが対象チェーン、対象資産、および外部準備金アドレスを入力したとき、ReserveFlow Creditは準備金アカウントとして登録しなければならない。
2. もし入力されたアドレスが対象チェーンの形式に適合しない場合、ReserveFlow Creditは登録を拒否し、入力項目を特定したエラーを表示しなければならない。
3. ユーザーが登録済みの準備金アカウントを表示したとき、ReserveFlow Creditは対象チェーン、対象資産、アドレス、および現在の検証状態を表示しなければならない。
4. ユーザーが自身のポジションに属さない準備金アカウントを変更または与信対象として使用しようとしたとき、ReserveFlow Creditはその操作を拒否しなければならない。

### Requirement 3: 準備金証明の申請と検証状態
**Objective:** As a 準備金保有者, I want 外部チェーンの入出金を証明として申請する, so that 準備金の変化を信用ポジションへ反映できる

#### Acceptance Criteria
1. ユーザーが登録済みアカウントに対応するトランザクション識別子を提出したとき、ReserveFlow Creditは証明の検証申請を作成しなければならない。
2. 証明が申請済みで検証結果が未確定である間、ReserveFlow Creditは少なくとも申請済み、検証待ち、利用可能、完了、失敗のいずれかの状態を表示しなければならない。
3. FDCがトランザクションの存在、対象送付先、金額、および対象資産を有効と確認したとき、ReserveFlow Creditは証明を検証済みとして扱わなければならない。
4. もしFDCによる検証が失敗した場合、ReserveFlow Creditは準備金または与信枠を更新せず、失敗状態と利用者が確認できる理由を表示しなければならない。
5. もし証明が登録済みアカウントまたは対象資産と一致しない場合、ReserveFlow Creditはその証明を拒否しなければならない。

### Requirement 4: 検証済み準備金台帳
**Objective:** As a 準備金保有者, I want 検証済みの準備金残高を確認する, so that 与信の根拠を追跡できる

#### Acceptance Criteria
1. 検証済みの入金証明が確定したとき、ReserveFlow Creditは対応する準備金残高を増加させ、最終検証時刻と証明識別子を記録しなければならない。
2. 検証済みの出金証明が確定したとき、ReserveFlow Creditは対応する準備金残高を減少させ、更新後の残高を与信計算に使用しなければならない。
3. もし同じ証明識別子が再度提出された場合、ReserveFlow Creditはその証明を再利用せず、準備金残高および与信枠を再度変更してはならない。
4. ユーザーが準備金の詳細を表示したとき、ReserveFlow Creditは検証済み残高、対象チェーン、対象資産、最終検証時刻、および証明状態を表示しなければならない。
5. ReserveFlow Creditは、未検証または失敗した証明を準備金残高として扱ってはならない。

### Requirement 5: 価格評価とデータ鮮度
**Objective:** As a 準備金保有者, I want 準備金の現在価値とデータの鮮度を確認する, so that 借入可能額を信頼して判断できる

#### Acceptance Criteria
1. 検証済みの準備金を評価するとき、ReserveFlow CreditはFTSOから取得した対象資産の価格を用いて米ドル建て評価額を算出しなければならない。
2. 価格または準備金証明が設定された有効期限内である間、ReserveFlow Creditはそれぞれを与信計算に使用しなければならない。
3. もし価格データまたは準備金証明が設定された有効期限を超えた場合、ReserveFlow Creditは当該データを新規借入の根拠として使用してはならない。
4. ユーザーが準備金の詳細を表示したとき、ReserveFlow Creditは使用中の価格、米ドル建て評価額、価格の更新時刻、証明の最終検証時刻、および各データの鮮度状態を表示しなければならない。

### Requirement 6: リスク調整与信枠と説明可能性
**Objective:** As a 準備金保有者, I want リスク調整後の借入可能額を理解する, so that 価格変動を考慮して安全に借入できる

#### Acceptance Criteria
1. 検証済み準備金または有効な価格が更新されたとき、ReserveFlow Creditは設定済みの資産別Haircutおよび最大LTVを適用して、リスク調整後準備金価値と信用枠を再計算しなければならない。
2. ReserveFlow Creditは、利用可能額を信用枠から借入残高を差し引いた値として表示しなければならない。
3. ReserveFlow Creditは、健全性指標を信用枠と借入残高の関係として算出し、設定済みの閾値に基づく状態を表示しなければならない。
4. ユーザーが与信枠の詳細を表示したとき、ReserveFlow Creditは準備金評価額、適用Haircut、リスク調整後価値、最大LTV、信用枠、借入残高、利用可能額、および健全性指標を表示しなければならない。
5. もし借入残高が再計算後の信用枠を超えた場合、ReserveFlow Creditはポジションを危険状態として表示し、新規借入を許可してはならない。

### Requirement 7: テスト用ステーブルコインの借入
**Objective:** As a 健全なポジションを持つ借入者, I want 利用可能額の範囲でテスト用ステーブルコインを借りる, so that 売却やブリッジなしに流動性を得られる

#### Acceptance Criteria
1. ユーザーが借入額を入力したとき、ReserveFlow Creditは借入後の借入残高、利用可能額、および健全性指標を表示しなければならない。
2. ユーザーが利用可能額以下の借入を要求し、準備金証明と価格データが有効であり、ポジションが健全であり、緊急停止中でないとき、ReserveFlow Creditはテスト用ステーブルコインを借入者へ提供し、借入残高を更新しなければならない。
3. もし要求額が利用可能額を超える場合、ReserveFlow Creditは借入を拒否し、超過額または利用可能額を表示しなければならない。
4. もし準備金証明または価格データが鮮度要件を満たさない場合、ReserveFlow Creditは新規借入を拒否し、鮮度不足のデータを特定して表示しなければならない。
5. ポジションが警告または危険状態である間、ReserveFlow Creditは状態に応じて新規借入を制限し、拒否理由を表示しなければならない。

### Requirement 8: 返済
**Objective:** As a 借入者, I want 借入残高を返済する, so that ポジションの健全性と利用可能額を回復できる

#### Acceptance Criteria
1. ユーザーが返済額を入力したとき、ReserveFlow Creditは返済後の借入残高、利用可能額、および健全性指標を表示しなければならない。
2. ユーザーが0より大きく借入残高以下の返済を実行したとき、ReserveFlow Creditは借入残高を返済額分だけ減少させ、与信状態を再計算しなければならない。
3. もし返済額が借入残高を超える場合、ReserveFlow Creditは借入残高を超える返済を受け付けず、許容される最大返済額を表示しなければならない。
4. 新規借入が緊急停止または危険状態により制限されている間、ReserveFlow Creditは返済操作を許可しなければならない。

### Requirement 9: リスク監視と緊急停止
**Objective:** As a 借入者, I want 準備金と価格に起因するリスクを把握する, so that ポジション悪化に対処できる

#### Acceptance Criteria
1. 検証済み出金、価格下落、証明の失効、または価格更新停止により与信条件が変化したとき、ReserveFlow Creditは信用枠、利用可能額、および健全性指標を再計算しなければならない。
2. もし健全性指標が設定済みの警告閾値を下回った場合、ReserveFlow Creditはリスクアラートを表示し、新規借入の可否を明示しなければならない。
3. もし健全性指標が設定済みの危険閾値を下回った場合、ReserveFlow Creditは新規借入を停止し、必要な返済またはリスク低減行動を表示しなければならない。
4. もし価格データ、準備金証明、またはFDC検証の信頼性が保証できない場合、ReserveFlow Creditは新規借入を緊急停止しなければならない。
5. 緊急停止中である間、ReserveFlow Creditは停止理由と影響を受ける操作を表示し、返済を許可しなければならない。

### Requirement 10: 状態、履歴、およびリスクの可視化
**Objective:** As a 借入者, I want 信用ポジションの状態と変化履歴を確認する, so that 与信判断とリスク変化を追跡できる

#### Acceptance Criteria
1. ユーザーがダッシュボードを表示したとき、ReserveFlow Creditは準備金評価額、リスク調整後価値、信用枠、利用可能額、借入残高、健全性指標、準備金カバレッジ、および有効なリスクアラートを表示しなければならない。
2. ユーザーがリスクモニターを表示したとき、ReserveFlow Creditはデータ鮮度、資産集中度、および新規借入の可否を表示しなければならない。
3. ユーザーが想定する価格下落率を指定したとき、ReserveFlow Creditは現在の準備金と借入残高を基にした想定信用枠、健全性指標、および状態を表示しなければならない。
4. 準備金登録、証明申請、証明完了・失敗、準備金更新、信用枠更新、借入、返済、リスクアラート、または緊急停止が発生したとき、ReserveFlow Creditは時刻、イベント種別、および結果を履歴として記録しなければならない。
5. ユーザーが履歴を表示したとき、ReserveFlow Creditは自身のポジションに関連するイベントを新しい順に表示しなければならない。

### Requirement 11: MVPの安全境界
**Objective:** As a デモ利用者, I want MVPの安全境界を理解する, so that テスト環境の機能を本番融資と誤認しない

#### Acceptance Criteria
1. ユーザーが借入画面を表示したとき、ReserveFlow Creditは借入資産がテスト用ステーブルコインであり、本番融資ではないことを表示しなければならない。
2. ReserveFlow Creditは、実資産による融資、法定通貨への換金、または本番運用を提供してはならない。
3. ユーザーがMVPの対象外である複数資産または複数チェーンを同時に与信へ使用しようとしたとき、ReserveFlow Creditはその操作を受け付けてはならない。
